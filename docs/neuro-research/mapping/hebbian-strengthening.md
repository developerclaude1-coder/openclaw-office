# hebbian-strengthening
MECHANISM: Hebbian plasticity / LTP-LTD: correlation-gated, synapse-local, bidirectional weight updates (NMDA AND-gate -> Ca2+ sign decoding -> AMPAR trafficking), stabilized by BCM sliding threshold and multiplicative homeostatic scaling.
ETTZ EQUIVALENT: Three candidate carriers: (a) the BANK's usage balances (derived from spine envelopes) + specced CHOICE envelopes; (b) procedures' worked->verified / failed->contested / superseded counts; (c) claims' trials (+confirm/-fail) with close-the-window-never-delete. Supporting signal plumbing: the trigger fabric's confirming envelope (the acknowledgment/back-propagating-spike analog, Markram 1997, PMID:8985014) and flow refs (the locality/site tag).
VERDICT: partial

## Argument for
The core Hebbian computation is use-plus-outcome coincidence driving an item-local, bidirectional, non-destructive weight update — and procedures and claims genuinely have it. A procedure's count updates only when it is USED and an OUTCOME arrives (worked->verified, failed->contested): that is a two-factor AND gate on the update, not a mere use counter (Nowak 1984, PMID:6320006 — the write-enable requires both events). The write is item-granular, like CaMKII's spine-local latch (Lisman 2012, PMID:22334212). It is bidirectional: contested/superseded weakens standing without destroying the record, which is precisely LTD's semantics — graded withdrawal of AMPA receptors while the synapse persists, resource recycled, structure intact (Malinow & Malenka 2002, PMID:12052905; Dudek & Bear 1992, PMID:1350090). And it is performance-driven, not clock-driven: 'a procedure never decays from disuse, only from failing when tried' matches the finding that LTD requires ACTIVITY (900 low-frequency trials), not silence. Claims' trials are the same logic on beliefs, and the closed window as the record of changed understanding matches biology's extinction-as-competing-record rather than deletion (Bouton 2004, PMID:15466298). The trigger fabric's confirming envelope even supplies the acknowledgment signal biology uses for credit assignment (Markram 1997, PMID:8985014). CHOICE envelopes ('considered X, picked Y, because Z') are specced credit-assignment infrastructure: considered-but-bypassed is exactly the deprecation-eligible class STDP's post-before-pre branch identifies (Bi & Poo 1998, PMID:9852584).

## Argument against
Four failures. (1) The named target — BANK usage balances — is NOT Hebbian: it counts use alone, with no post-signal, no outcome correlation, no coincidence window. Biology never strengthens on presynaptic traffic alone; glutamate without depolarization writes nothing (Nowak 1984, PMID:6320006). A raw use counter will happily strengthen a prompt that is used often and fails often. (2) No actuation: in biology the weight IS the gain — receptor count changes every future response (Malinow & Malenka 2002, PMID:12052905). ETTZ balances and verified counts are ledger statistics; per the owner's brief nothing ranks retrieval, admits to a cache, or cheapens a path based on them (that is why 'myelination-as-precomputation' is still an open design question). A weight that does not affect readout is a log, not a synapse. (3) No LTD for bank entries: short of quarantine, nothing weakens a bank item; CHOICE envelopes are specced, not landed, so why-not-used is not yet learnable. (4) No stability supervision at all: no homeostatic scaling (Turrigiano 1998, PMID:9495341), no sliding threshold (BCM, PMID:7054394), no fast read-time normalization (Carandini & Heeger 2012, PMID:22108672). Any ranking naively bolted onto balances would be positive-feedback-unstable: high balance -> ranked first -> chosen more -> higher balance — textbook runaway winner-take-all, the software twin of maladaptive myelination locking in the wrong path. Also missing per the critique: a seconds-scale eligibility window for episode-level credit (Bittner 2017, PMID:28883072 — the ±20 ms STDP window actively misleads here) and any salience/write-priority gate (Schultz 1997, PMID:9054347).

## Strongest objection
'Partial' is too generous — the verdict should be 'missing.' The essence of a synaptic weight is that it changes downstream computation; every ETTZ counter named here is descriptive, not causal. If verified counts, trials, and balances alter no retrieval order, no cache, no selection, then ETTZ has bookkeeping ABOUT strength but no strength — you have mapped the ledger to the synapse and forgotten the current that flows through it.

## Verdict survives because
The objection is true of the BANK but false of procedures, and one genuine carrier is enough for 'partial.' A superseded procedure is a 'permanent known-bad pointer' — that changes future behavior: the known-bad path is not re-tried, and verified vs contested status is read at cue time (procedures are cued by task context) and conditions what gets attempted. That is a weight affecting readout, in exactly LTD's direction. Claims' bi-temporal windows likewise actuate: an --asof query and any consumer of state.json returns different answers after a window closes. So the update rule (use+outcome, local, bidirectional, non-destructive) AND at least a coarse actuation path both exist — what is missing is graded strengthening that actuates (ranking/caching), LTD for the bank, and normalization. That is the definition of 'partial with named missing pieces,' not 'missing.' Conversely 'have it' fails because the mapping's own named target (bank balances) lacks the AND gate, and no stability tier exists anywhere — biology treats that tier as non-optional (pure Hebbian rules are unstable by construction, BCM PMID:7054394).

## Missing pieces
- Outcome-coupling in the BANK: balances count use, not use-AND-confirmed-outcome; the coincidence gate (Nowak 1984, PMID:6320006) is absent from the named target
- Actuation: no weight (balance, trial count, verified count) changes retrieval ranking, cache admission, or path cost — strength is recorded but never applied (contrast Malinow & Malenka 2002, PMID:12052905: weight = gain)
- LTD for bank entries: no graded weakening operator short of quarantine; CHOICE envelopes (the considered-but-bypassed signal, STDP's depress branch, Bi & Poo 1998, PMID:9852584) are specced but not implemented
- Homeostatic normalization: nothing renormalizes balances multiplicatively to prevent runaway winner-take-all (Turrigiano 1998, PMID:9495341), and no BCM sliding threshold makes a busy item's bar for further strengthening rise (PMID:7054394)
- Seconds-scale eligibility window for credit assignment around a confirming envelope — behavioral-timescale plasticity, order-symmetric, one-trial-capable (Bittner 2017, PMID:28883072)
- Salience/write-priority gate: nothing computes which uses deserve extra credit (dopamine reward-prediction-error analog, Schultz 1997, PMID:9054347); every confirmed use currently counts the same
- Read-time arbitration: no divisive-normalization-style competition when several bank items or procedures match a cue (Carandini & Heeger 2012, PMID:22108672)

## Adoptable proposal: Outcome-coupled efficacy view for the BANK (Hebbian ledger, derived-only)
- biological principle: Hebbian two-factor update with LTD and homeostatic scaling: strengthen an item only when its use co-occurs, within a seconds-to-minutes eligibility window on the SAME flow ref, with a confirming envelope (use AND outcome — the NMDA AND-gate, Nowak 1984; the confirming envelope as back-propagating acknowledgment, Markram 1997); depress items considered-but-bypassed or active in flows that end in error envelopes (Bi & Poo 1998; Dudek & Bear 1992 — weakening as graded withdrawal, never destruction); window sized per Bittner 2017 (seconds-scale, symmetric), not STDP milliseconds; periodically renormalize all efficacy scores multiplicatively to a fixed total so ratios (the learned information) survive while total gain is bounded (Turrigiano 1998).
- ettz change: Add one derived, recomputable 'efficacy' score per bank item, computed at fold time from envelopes that already exist or are already specced: (+) credit when a usage/CHOICE envelope for the item shares a flow ref with a confirming envelope arriving within the eligibility window; (-) debit on considered-but-bypassed CHOICE envelopes and on same-flow error envelopes; nightly multiplicative renormalization to a fixed sum during memory-nightly's fold. Actuation limited to the cheapest form: efficacy orders bank retrieval/suggestion (ranking only — no cache admission, no precompute yet). Raw balances and all envelopes are untouched; efficacy is a state.json-style render, deletable and refoldable, never authoritative. Prerequisite explicitly surfaced: land the CHOICE envelope spec, since the depress branch cannot exist without it.
- cost: Build: small — one scoring function in the fold, one field in the bank's rendered state, ranking hook in bank retrieval; the envelope substrate (usage, CHOICE, confirming, error, flow refs) already exists or is specced. Runtime: incremental per-envelope work inside the existing nightly fold plus a trivial renormalization pass; no new organ, no new store, no wire protocol change. The known 60s+ cold-fold scaling pain is the main runtime exposure — the score should be computed incrementally from the fold cursor, not by refolding 71k envelopes.
- risks: (1) Credit misassignment: a confirming envelope credits bystander items merely active in the window — the false-correlation failure Hebb is famous for; mitigation is the two-key gate (same flow ref AND in-window), mirroring tag-plus-capture (Frey & Morris 1997). (2) Feedback loop: efficacy ranks retrieval -> ranked items get chosen -> efficacy rises — without the multiplicative renormalization AND a BCM-style rising bar for already-strong items, early winners lock in permanently (the software twin of maladaptive myelination); the normalization is therefore not optional polish, it ships in v1 or the feature is unstable by construction. (3) Entrenched-wrong-item: an item that confirms often in one narrow context outranks a better general item; biology's fix (prediction-error-gated reopening, Sevenster 2013, PMID:23413355) is out of scope here and should be named as the follow-on. (4) Doctrine breach by implementation error: if efficacy is stored as mutable authoritative state rather than a derived render, it violates append-only; the guard is that a full refold from envelopes must reproduce it bit-for-bit. (5) Where the biological principle would be WRONG for ETTZ: Hebbian strengthening entrenches and specialises — it is anti-generalisation. Ranking the bank harder makes ETTZ better at what it already does and does nothing for the owner's sharpest gap (no episodic->semantic promotion); it must not be sold as progress on that gap, and biology warns the two must ship as a pair.
- owning session: the bank (score definition and retrieval ranking), with memory-nightly executing the fold-time scoring and renormalization; kallimachos/entropy A-003 explicitly NOT involved — depression here is rank demotion, not disposal.
- priority argument: Ranks high-but-second among the estate's proposals. High because it is cheap, fully doctrine-compliant (derived view over an untouched append-only substrate; its LTD is demotion, biology's own non-destructive weakening), directly answers an owner design question ('what would real strengthening look like'), and is the PREREQUISITE for myelination-as-precomputation — no route should be compiled/cached until strength is outcome-valid rather than use-valid, or the estate precomputes its own bad habits. Second, not first, because it is an optimization of an existing capability, while the episodic->claims promotion gap is an absent capability; by the owner's own suspicion that gap is sharper, and this proposal explicitly does not close it.

## Doctrine notes
Three explicit touches on owner law. (1) Never-erase: LTD is the encouraging precedent, not a tension — biology's primary weakening operator withdraws a recyclable resource while the structure persists (Malinow & Malenka 2002); that is window-closing/demotion semantics, so bidirectional weight updates are adoptable without any delete path. The proposal's depress branch demotes rank only; it never routes to entropy/quarantine, and disposal remains owner-gated as law requires. (2) Append-only core: homeostatic renormalization mutates weights in place in biology; in ETTZ it must live entirely in the derived/rendered layer (a fold output, reproducible from envelopes), never as a rewrite of any envelope, balance history, or trial record — a stored-mutable efficacy would be a doctrine violation dressed as biology. (3) Nothing-builds-until-he-rules: this is a proposal for owner review; the one sequencing note put to him is that the renormalization tier is load-bearing (pure Hebbian rules are unstable by construction, BCM PMID:7054394; Turrigiano PMID:9495341) and should not be severable from the ranking tier in any approval.
